# 足跡圖（Footprint）實作筆記

這份文件記錄「每個價位的主動買賣量」，也就是足跡圖（Footprint chart，又叫訂單流圖）怎麼做。**已經實作**（工具列的「足跡圖」），第 1～3 節是評估時的背景，第 4 節起是實際做法和實測數字。

比較簡單的那一層是**每根 K 棒的主動買賣拆分**：成交量副圖把量柱分成兩段，下段是主動買、上段是主動賣，還有縮量標示。足跡圖是把這個拆分再細分到「每個價位」。

---

## 1. 足跡圖是什麼

每根 K 棒旁邊，依價位一格一格列出這根 K 棒裡：

```
          賣 × 買
83,420    12 × 3
83,410    40 × 18     ← 左邊：主動賣（吃掉買單）
83,400   105 × 230    ← 右邊：主動買（吃掉賣單）
83,390    31 × 92
```

- **主動賣（bid 側）**：taker 是賣方，砸在買單上。
- **主動買（ask 側）**：taker 是買方，買在賣單上。
- 常見的加值資訊：
  - 每格的差值（買 − 賣）。
  - 每根的 POC：成交最多的價位。
  - **失衡（imbalance）**：斜對角比較，某價位的主動買是下一格主動賣的 3 倍以上，就標色。
  - 每根底部的總 Delta。

CoinGlass 這種圖在圖表模式裡，不在一般的指標清單中，可以找「足跡圖」或「Footprint」。

## 2. 和已完成的「K 棒買賣拆分」差在哪

| | K 棒買賣拆分（已完成） | 足跡圖（本文件） |
|---|---|---|
| 精細度 | 每根 K 棒一組數字 | 每根 K 棒 × 每個價位 |
| 資料來源 | K 線本身的 `takerBuyBaseVolume`（`k[9]`／串流 `k.V`） | 逐筆成交 `aggTrade` |
| 歷史資料 | 跟 K 線一起拿，免費 | 要逐筆下載，只補最近 3 小時，其餘靠開著時累積 |
| 快取 | `bars2` 快取（每筆紀錄 8 個欄位） | `footprint/` 快取（每分鐘一段，長度不固定，只留 12 小時） |

## 3. 資料來源

### 3.1 即時：`<symbol>@aggTrade` 串流

hub 本來就為每張卡訂閱了 aggTrade（`binance.js` 的 `aggTradeStream()`，讓 K 棒收盤價跳得比 kline 快）。足跡在 `dispatch()` 的 `aggTrade` 分支多交給 `FootprintCollector` 一份。

| 欄位 | 意義 |
|---|---|
| `p` | 成交價（字串的小數位數就是價格精度，用來把價格換成整數 key） |
| `q` | 數量（幣），小數位數同樣決定存檔用的整數單位 |
| `m` | **買方是 maker**：`true` 代表 taker 是賣方，算主動賣；`false` 算主動買 |
| `T` | 成交時間（毫秒），決定落在哪一分鐘，不用收到訊息的時間 |
| `a` | aggTrade ID，連續遞增，用來判斷有沒有漏收 |

### 3.2 歷史：REST `aggTrades`

- 合約 `GET /fapi/v1/aggTrades`：**權重 20**，IP 上限每分鐘 2400；只查得到最近 48 小時。現貨 `GET /api/v3/aggTrades`：權重 4，上限 6000。
- 一次最多 1000 筆；`startTime`／`endTime` 區間要小於 1 小時；跟 `fromId` 不要同時帶。
- **實測量**（2026-10-15，最近一分鐘）：BTCUSDT 永續 3,634 筆、4 次請求、1,153 個價位；ETHUSDT 2,910 筆、3 次、560 個價位；DOGEUSDT 342 筆、1 次、15 個價位。
- 做法：一次補一分鐘（`startTime`＝分鐘開頭、`endTime`＝結尾），滿 1000 筆就用 `fromId` 往後翻，直到成交時間超過這分鐘。

### 3.3 完整度

aggTrade ID 連續，所以不用跟 kline 的 volume 對帳就能判斷：

- 一分鐘**完整**＝它的每一筆都在同一段沒跳號的串流裡收到，而且這段串流在這分鐘開始前就已經在收（看到了上一分鐘的最後一筆）。
- 這要等下一分鐘的第一筆到了才知道（才確定這分鐘最後一筆之後沒漏），所以一分鐘在那時才「收盤」。
- 中間沒有任何成交的分鐘：前後兩筆 ID 連續，就是一分鐘空的、完整的。
- 不完整的分鐘（卡片剛開的那分鐘、重連跨過的、程式關著時的）收盤後整分鐘用 REST 重抓，取代串流版本。只有完整且收盤的分鐘會存檔。

## 4. 實際架構

```
  hub                                        card
 ┌──────────────────────────────┐           ┌──────────────────────────────┐
 │ aggTrade 串流                 │           │ FootprintBook                │
 │  └→ FootprintCollector（每幣一個）│ ─IPC→     │   分鐘 → K 棒（5m＝5 個 1m 相加）│
 │      分鐘 × 原始價位 → [賣, 買]   │ 快照＋更新 │ FootprintPrimitive           │
 │      完整度、REST 補資料（每秒 1 次）│           │   依縮放合併成列、POC、失衡、Delta │
 └──────────────────────────────┘           └──────────────────────────────┘
        │ 收盤且完整的分鐘
        ▼
  main/footprint-store.js → userData/footprint/{_perp/}{SYMBOL}/{hourStart}.fp
```

- 卡片開啟足跡時呼叫 `setFootprint(subId, true, fromSec)`：hub 先讀存檔，回傳目前有的全部分鐘（快照），之後每一分鐘的變化（形成中的那分鐘每 250ms 一次、收盤、REST 補到的）都經 `datafeed:footprint` 推給卡片。
- 卡片端以「形成中 < 收盤但不完整 < 收盤且完整」的順序判斷新舊，快照和更新在路上交錯時，不會把已經確定的分鐘換回舊版本。
- 範圍：最近 30 根、最多 6 小時（卡片和 hub 各存一份 1 分鐘原始價位的資料，BTC 一分鐘約 30KB）。REST 只補最近 3 小時，更早的只來自存檔。

### 4.1 存檔格式

每分鐘一個 gzip 段，直接附加到該小時的檔案（gzip 段可以串接，解壓時當成一個串流讀回）。段內全是無號變長整數：

```
[分鐘] [log10 價格倍率] [log10 數量倍率] [firstId] [lastId − firstId]
[價位數] [第一個價格 key] 然後每個價位：[跟上一個 key 的差] [主動賣] [主動買]
```

- 價格 key ＝ 價格 × 10^小數位數，連續價位的差是 1，只占 1 byte。
- 數量存成最小單位的整數，不失真。
- **實測**：BTCUSDT 永續一分鐘約 1,300 個價位，float64 格式約 25KB，這樣存約 2.3KB；合併成 1 美元一格約 0.5KB（但不需要，合併只在畫圖時做）。12 小時約 1.5MB。
- 只保留最近 12 小時，每次寫入時刪掉更舊的檔案。
- 寫到一半被砍掉：讀檔失敗時用 `Z_SYNC_FLUSH` 救回斷點前的分鐘，並重寫檔案，免得之後附加的分鐘也讀不到。

### 4.2 呈現（`renderer/footprint-primitive.js`）

- 開啟時 K 棒變成空心，左右兩排畫在 K 棒後面，數字和框畫在前面。
- **K 棒寬 < 72px**：左右兩排橫條，每列目標 4px 高，長度以該根最大的一邊為準；失衡畫實色，其他半透明。
- **K 棒寬 ≥ 72px**：每列「賣 買」數字，目標 14px 高，底色深淺代表量；失衡粗體上色。
- 列高＝原始價位的 1、2、5 × 10ⁿ 倍，邊界對齊整數倍。
- POC 用橘框；圖表底部印每根的 Delta（寬度 ≥ 22px 時）。
- 不完整（還沒補齊）的 K 棒畫淡，Delta 前面加 `~`。
- **失衡**：斜對角比較。某列主動買 ≥ 下一列主動賣的 N 倍、或主動賣 ≥ 上一列主動買的 N 倍（N 可選 2／3／4，預設 3）；對面是 0 不算，否則每根最上和最下一列都會亮。

## 5. 之後可以加的

- 十字線停在某一列時，讀數顯示該列的買、賣、差值（現在要放大到數字模式才看得到數字）。
- 連續失衡（同方向 3 列以上）標成區間，常被當作支撐壓力。
- 累積 Delta（CVD）副圖：可以直接從 K 線的 `buyVolume` 算，不需要足跡資料。
- 現貨與永續都能用；現貨的 REST 權重低，補資料可以更快。
