# 交易內部設計

委託怎麼從下單票送到幣安，以及一路上的保護。怎麼交易見[下單說明](../guide/trading.zh-TW.md)。

## 交易在哪裡執行

所有跟錢有關的事都在**主行程**（`main/trading/`）：金鑰、簽名、REST、使用者推送和委託狀態。卡片畫面只透過白名單 preload API 送出意圖（「在 2551.5 做多 200 USDT，止盈設在這裡」），拿回來的是要畫的狀態。

| 環境 | 交易所 | 金鑰 |
| --- | --- | --- |
| 模擬（本機） | `main/trading/paper.js`，回應跟幣安相同的呼叫 | 不需要 |
| 測試網（預設） | 幣安模擬交易 | 模擬交易的金鑰 |
| 正式 | 幣安 U 本位永續 | 你的金鑰；切換需要另外確認 |

## 金鑰

- HMAC 的 Secret，或自行產生的 Ed25519 / RSA 私鑰，用 Windows **DPAPI** 加密（`main/trading/vault.js`），存在 `userData/trading-credentials.bin`。DPAPI 綁定你的 Windows 帳戶：檔案被複製到別的帳戶或電腦也解不開。
- 私鑰檔由主行程直接從檔案對話框讀取，不會經過任何畫面。幣安那邊只有你上傳的公鑰。
- 畫面永遠只看得到末四碼和金鑰類型。
- 幣安永續的文件只列出 HMAC 和 RSA，但 Ed25519 已用正式帳戶實測可用（唯讀查詢，簽名驗證通過）。

## 送出之前

- **依交易所規則取整**，在主行程進行：價格依最小跳動、數量依步長、最小名目價值，規則來自 `exchangeInfo`（`main/trading/rules.js`）。畫面送不出沒有取整的數字。
- **槓桿記錄在帳戶上**：幣安依幣種保存（`GET /fapi/v1/symbolConfig` 讀、`POST /fapi/v1/leverage` 寫），所以 App、網頁、手機看到的一樣。每次打開下單票都重新讀，送單時不會被改。`GET /fapi/v1/leverageBracket` 的分層讓倉位越大最高槓桿越低，下單票會在送出前用預估倉位對照。
- **按兩下**：第一下只會讓按鈕變成確認狀態，並把要送出的內容完整寫出來，包括資產、數量和價格（美股和商品永續還會標「傳統資產」）。3 秒內按第二下才送出。

## 委託編號一位都不能錯

幣安的委託編號可能超過 16 位數，而 JavaScript 的數字只有 15～16 位有效位數，用一般的 `JSON.parse` 讀進來最後幾位會被四捨五入（`8389765907134201345` 變成 `8389765907134202000`）。線照樣畫得出來，因為畫線只需要價格，但取消和改價送出的是不存在的編號，幣安回 `-2011 Unknown order sent`。所以交易相關的回應都用 `parseExact` 解析：16 位數以上的整數原樣保留成字串。

## 改價

- **限價單**用 `PUT /fapi/v1/order` 原單修改：委託編號不變，但會重新排隊（幣安的規則）。
- **止盈止損**是條件單，幣安**沒有修改的 API**，只能取消再重掛。同方向的整倉平倉條件單不能同時存在兩張，所以先取消舊的。新的被拒絕時（例如觸發價已經被穿過），**會立刻把原本的價格掛回去**，倉位不會沒有止損；連恢復都失敗才會跳錯誤請你檢查。
- 拖曳結束在錯的一邊、按 `Esc` 取消、移動不到 3px，或拖曳期間價格刻度變了，都不會送出。

## 反手

**平常是一張單。** 反手送一張反方向、數量是倉位兩倍的單（持多 0.01 → 賣出 0.02：前 0.01 平倉、後 0.01 開空），而不是「先平再開」兩張。只成交一次、中間沒有空手的空檔，手續費兩種做法一樣。

**保證金放不下一張單時改成兩張。** 原倉位的保證金要等成交後才釋放，所以新開的那一半得在原倉位旁邊放得下，倉位用掉大約一半以上資金時就放不下。這時改成先送只減倉平倉、再開同樣大小的反向倉。是否要拆，依最近一次讀到的帳戶估算（新倉的一半 ÷ 槓桿 ＋ 吃單手續費，留 2% 緩衝）；若估算說夠、幣安仍回 `-2019`，那張單什麼都沒做，會自動改走兩張。

**限價**反手拆成兩張時，先在你的價格掛只減倉平倉單。全部成交、倉位歸零後，再用同一個價格掛開倉單（價格已越過就立刻以該價或更好成交，否則掛著等），並帶上反手設定的止盈止損。平倉單被取消、只成交一部分或沒有歸零時，不會送開倉單；開倉失敗時你會是空手，通知會明講。

保護機制：

- **確認的數量就是送出的數量**：面板寫「多 0.01」，送出前向幣安重新取一次倉位，數量不一樣就不送。
- **原倉位的止盈止損與減倉單，在反手成交之後才取消。** 多單的止損是「賣出」，反手成空單後留著沒有意義，所以會清掉；但成交之前它還在保護原倉位，所以限價反手掛著時不會先動它。部分成交、已經越過零軸時也會清掉。
- **倉位守衛**：限價反手掛著時，倉位可能先因為別的事改變，例如原本的止損觸發、或你手動平倉。這時兩倍數量的單一成交就會開出**兩倍的反向倉位**。所以每次更新倉位都會檢查「倉位 = 原倉位 + 這張單已成交的量」，不成立就自動取消反手單並跳出提醒。倉位和掛單是同時讀的，成交剛好落在兩次讀取之間也會看起來對不上，所以不一致時會再依序讀一次（委託 → 倉位 → 委託），委託在這段時間沒變、而且仍然對不上才取消。
- 同一個幣種一次只能有一張反手限價單。

## 保持狀態最新

盈虧用標記價格每秒計算。倉位與訂單同時走兩條路：幣安的使用者推送（成交當下就更新），以及每 3～12 秒一次的 REST 輪詢當保險，推送斷線時畫面也不會停在舊資料上。等限價單成交才掛的止盈止損，在看到成交時掛上，包括程式關著時發生的成交。

成交通知也來自同樣的更新：掛著的單被吃、或止盈止損觸發，就算沒開那個幣的卡片也會通知；送出當下就成交的單只在卡片裡顯示。

## 模擬交易所

`main/trading/paper.js` 回應跟幣安 API 相同的呼叫，所以三種環境的交易程式只有一套；`paper-engine.js` 負責帳務。它用幣安的即時資料撮合：真實成交價穿過掛單價才算限價成交，市價單和止盈止損吃真實掛單簿（前 50 檔）算滑價，資金費依幣安公布的費率結算，全倉強平以標記價格計算。程式關著的期間（最多 30 天）用 1 分 K 和公布的資金費率補算，同一分鐘內先算止損、再算止盈。規則列在[模擬交易](../guide/paper-trading.zh-TW.md#成交與成本怎麼算)。

## 用模擬交易所開發

`STOCKCARD_TESTNET_REST` 和 `STOCKCARD_TESTNET_WS` 可以把**測試網**環境指到本機的模擬交易所（在 `main/trading/client.js` 讀取）。正式環境的網址不能被覆寫。
