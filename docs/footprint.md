# 足跡圖（Footprint）實作筆記

這份文件記錄「每個價位的主動買賣量」，也就是足跡圖（Footprint chart，又叫訂單流圖）該怎麼做。目前**還沒有實作**，先把評估時想清楚的細節寫下來，之後要做時從這裡開始。

已經完成的是比較簡單的那一層：**每根 K 棒的主動買賣拆分**。成交量副圖會把量柱分成兩段，下段綠色是主動買、上段紅色是主動賣，還有縮量標示。足跡圖是把這個拆分再細分到「每個價位」。

---

## 1. 足跡圖是什麼

每根 K 棒旁邊，依價位一格一格列出這根 K 棒裡：

```
          賣 × 買
83,420    12 × 3
83,410    40 × 18     ← 左邊：主動賣（吃掉買單）
83,400   105 × 230    ← 右邊：主動買（吃掉賣單）
83,390    31 × 92
```

- **主動賣（bid 側）**：taker 是賣方，砸在買單上。
- **主動買（ask 側）**：taker 是買方，買在賣單上。
- 常見的加值資訊：
  - 每格的差值（買 − 賣）。
  - 每根的 POC：成交最多的價位。
  - **失衡（imbalance）**：斜對角比較，某價位的主動買是下一格主動賣的 3 倍以上，就標色。
  - 每根底部的總 Delta。

CoinGlass 這種圖在圖表模式裡，不在一般的指標清單中，可以找「足跡圖」或「Footprint」。

## 3. 資料來源

### 3.1 即時：`<symbol>@aggTrade` 串流

**現在已經有訂閱。** `renderer/datafeed/binance.js` 的 `aggTradeStream()` 讓 K 棒收盤價跳得比 kline 串流快，也用它累加主動買入量（見 `handleMessage` 的 `aggTrade` 分支）。足跡圖只要在同一個地方，多把每筆成交依價位累加起來。

每筆 aggTrade 用到的欄位：

| 欄位 | 意義 |
|---|---|
| `p` | 成交價 |
| `q` | 數量（幣） |
| `m` | **買方是 maker**：`true` 代表 taker 是賣方，算主動賣；`false` 算主動買 |
| `T` | 成交時間（毫秒），用它決定落在哪根 K 棒，不要用收到訊息的時間 |
| `a` | aggTrade ID，連續遞增，可以用來偵測漏收 |

### 3.2 歷史：REST `aggTrades`

- 合約：`GET /fapi/v1/aggTrades`；現貨：`GET /api/v3/aggTrades`。
- 一次最多 1000 筆，可以用 `fromId` 往後翻，或用 `startTime`／`endTime`（區間不能超過 1 小時）。
- **問題在量**：熱門合約（BTC、ETH 永續）在活躍時段，一分鐘可能有好幾千筆 aggTrade。要補 1000 根 1 分鐘 K 棒，就是上千次請求，會撞到 IP 權重上限，也要等很久。各端點的請求權重請以幣安官方文件為準，實作前先查。
- **結論**：歷史只補「最近一小段」，例如目前畫面上最右邊的幾十根，或是卡片開啟前的 30 分鐘。其他歷史只能從卡片開著的時候開始累積。

### 3.3 完整度檢查

每根 K 棒的足跡總量（買 + 賣）應該等於 kline 的 `volume`，主動買總量應該等於 `buyVolume`。可以用它判斷「這根足跡完整嗎」：

```
completeness = 足跡總量 / kline.volume
```

- 低於 99%：標為不完整，例如畫淡一點或加虛線框，避免誤判失衡。
- aggTrade ID 不連續（漏收）或 WebSocket 重連：把那段時間的 K 棒標為不完整。如果在短期回補的範圍內，用 REST 依 `fromId` 補齊。

## 4. 架構

```
  hub（datafeed）                    card
 ┌───────────────────────┐        ┌─────────────────────────────┐
 │ aggTrade 串流          │        │ FootprintPrimitive          │
 │   └→ FootprintStore    │ ─IPC→  │   K 棒夠寬才畫每格數字        │
 │       以 1m 為基本單位   │        │   不夠寬就退回量柱買賣拆分     │
 │       價位 → {bid, ask}│        └─────────────────────────────┘
 │ REST 短期回補           │
 └───────────────────────┘
        │ 收盤的 1m 足跡寫進快取
        ▼
  userData/footprint/{market}/{SYMBOL}/{chunk}.bin
```

### 4.1 基本單位：1 分鐘、最小跳動價位

- 一律以 **1 分鐘 × 最小跳動價位（tickSize）** 記錄。5 分鐘、15 分鐘、1 小時的足跡由 1 分鐘的相加得到，不用分開訂閱或分開存。
- 畫圖時的價位格大小 = tickSize × N。N 依縮放程度自動挑，例如每格至少 12px 高，數字才排得下。BTC 的 tickSize 是 0.1，原始格太細，一定要合併。
- 合併格時，價位要對齊到 tickSize × N 的整數倍，避免同一個價位在不同縮放下落在不同的格子。

### 4.2 記憶體與儲存

- 每根 1 分鐘 K 棒的價位數不固定，波動大的一分鐘可能有上百個 tick。
- 記憶體裡：`Map<barTime, Map<priceTick, [bid, ask]>>`。只保留畫面附近的範圍和最近 N 根（例如 1440 根 = 一天）。
- 磁碟格式（長度可變，不能沿用 `bar-store.js` 的固定寬度）：
  ```
  每根： [time f64][count u32][ (priceTick i32, bid f64, ask f64) × count ]
  ```
  按月分檔，只寫**收盤**的 K 棒，和 `bar-store.js` 同樣原則：未收盤的 K 棒不落地。另外在檔頭或旁邊記錄 completeness。

### 4.3 呈現

- **K 棒寬度 ≥ 約 60px** 才畫數字。格式是 `賣 × 買`，背景色深淺代表量的大小，失衡的格子用強調色。
- 比這窄的時候，數字一定擠不下，就退回目前的「量柱買賣兩段」，加上每根 POC 的小橫線。所以縮小看整體時不會一團亂。
- 每根底部顯示 Delta（買 − 賣）。正值用上漲色，負值用下跌色。
- 十字線停在某一格時，在讀數顯示該價位的買、賣、差值。
- 不完整的 K 棒畫淡一點，讀數註明「資料不完整」。

### 4.4 要注意的邊角

- **K 棒邊界**：用 `T`（成交時間）決定歸屬。跨分鐘的那一筆不能算進上一根。
- **重連**：重連期間漏收的 aggTrade，短期內可以用 REST `fromId` 補；超過回補範圍的，就標為不完整。
- **現貨和永續分開**：和 `bars2` 一樣，永續放在 `_perp` 底下。
- **多張卡片看同一個交易對**：足跡在 hub 收集一次，各卡片共用，不要每張卡片各訂一份。
- **CPU**：熱門交易對每秒可能有幾十到上百筆 aggTrade。累加本身很便宜，但重畫要節流，例如最多每 100ms 一次，跟現在 K 棒的更新頻率一致。

## 5. 建議的實作順序

1. 在 hub 收集 1 分鐘足跡，只放記憶體，先不存檔。用 completeness 對照 kline 驗證資料正確。
2. `FootprintPrimitive`：畫數字格、Delta、POC，加上寬度不足時退回量柱。
3. 短期 REST 回補（卡片開啟時補最近 30 分鐘）。
4. 存檔與多週期合併。
5. 失衡標示和相關設定（倍數門檻、格子合併方式）。
